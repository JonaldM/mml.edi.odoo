# mml_edi Go-Live Gate Review — 2026-07-02

Multi-agent review (4 dimensions, each adversarially verified; prod live-state inspected read-only).
Scope: Briscoes idempotency, Briscoes stock-safety/oversell, Animates spec compliance, ops readiness.

## Verdicts

| Area | Verdict |
|---|---|
| Briscoes idempotency | **GO-WITH-FIXES** |
| Briscoes stock safety | **NO-GO** |
| Animates go-live | **NOT-READY** |

### Briscoes idempotency

The sequential idempotency design is genuinely sound and live-proven (SHA-256 per-partner file dedup, marker-only-after-full-success, per-store savepoints, dup-safe partial-failure retry, deterministic per-exchange ACK key + retry cron; 722 prod log rows with zero errors). But both dedup layers are Python-only TOCTOU checks with no DB unique constraint or advisory lock (CONFIRMED blocker IDEM-1): a cron tick racing a manual 'Run Poll Now' (or two HTTP workers) creates duplicate confirmed SOs for the same Briscoes PO, and nothing at the DB layer rejects the second insert. Two confirmed majors compound it: the FTP rename + ORDRSP upload happen mid-transaction so a crash after rename silently loses the PO forever while Briscoes may hold an ACK for a rolled-back order (IDEM-2), and the ACK send-once guard double-sends on FTP ghost-success via the active 30-min retry cron (IDEM-3). Fixes are small and well-scoped (partial unique index + pg_advisory_xact_lock; per-file commit before rename; committed send-claim row). Until they land: never run manual polls near cron ticks, and treat any worker restart during a poll as requiring FTP inbox reconciliation.

### Briscoes stock safety

As deployed, there is NO oversell protection in the live flow: the prod Briscoes partner row is verified oos_policy='backorder' with auto_confirm_clean=t, under which a 1000-unit PO against zero stock is confirmed in full and the ORDRSP tells Briscoes full supply with no ABGRU (CONFIRMED blocker SS-2 — deliberately deferred pending Briscoes accepting short-confirm ORDRSPs, but it means the short-ship feature the gate is about is not actually active). Even after flipping to short_ship, the availability gate fires exactly once at parse time: approve-after-review (hours later), bulk approve, and ORDCHG qty increases all confirm and ACK stale quantities with no re-check and no reservation in between (CONFIRMED blocker SS-1, major SS-5), and correctness silently depends on unverified picking-type reservation config (major SS-3). What IS right: free_qty (not qty_available), island-DC-scoped, fail-safe to 0.0, correct clamp math, ABGRU=11 on short lines, fail-closed iDOC ACK defaults — the foundation is good, the enforcement points are missing. Path to GO: fix SS-1 (re-check + re-clamp at approve), assert/verify reservation (SS-3), gate ORDCHG increases (SS-5), get Briscoes' short-confirm sign-off, then flip oos_policy — and run the oversell drills below.

### Animates

Not close, at three independent layers. (1) Prod cannot even be configured: parsers/animates*.py are absent from the deployed tree, the deployed allow-list closes after BriscoesIDOCParser, and the deployed (stale) hard GST pricelist constraint would raise ValidationError on the live Animates pricelist id 663 (OPS-2). (2) The merged code itself has spec-fatal defects: every ORDRSP carries placeholder SUPPLIER_GLN, constant control ref 12341 and a frozen 2020 UNB timestamp (AN-01, reproduced by execution); the spec-mandated CONTRL acknowledgement is never emitted (AN-02); DESADV/INVOIC/SSCC have zero Odoo integration — no triggers, no SSCC minting, no sequences (AN-03/OPS-6); replacement POs silently drop new lines and price changes then ACK full acceptance (AN-04); cancellations break the ACK builder into an infinite retry loop (AN-05); any non-ASCII Latin-1 byte permanently breaks the ORDRSP (verified missed finding); missing-SOL lines default to accepted-in-full — the inverse of the Briscoes fail-closed default (SS-6); the spec forbids backorders yet 'backorder' is the default policy and CT carton lines would book as eaches (SS-7/AN-06). (3) Externally: no supplier GLN/vendor code/GS1 prefix/SPS transport confirmation (AS2/API would be a transport gap), no store seeding for ~66 stores, and TST1ANIMATES certification addressing is unsupported (OPS-5, AN-13, AN-14). The pure EDIFACT message layer (tokenizer, envelope validators, golden-fixture builders, ~198 passing tests) is solid and reusable — the Odoo integration half and the identity/config layer must be built, then SPS certification run end-to-end.

## Confirmed majors

1. [IDEM] FTP rename + ACK upload mid-transaction: dedup marker + '.processed' rename (models/edi_processor.py:236-242) and _queue_ack upload (:330) run inside the single uncommitted poll transaction; a worker death before end-of-request commit rolls back all DB state while the file stays archived — PO silently lost forever, and Briscoes may hold an ORDRSP for a rolled-back order. Fix: cr.commit() per file BEFORE move_to_processed (or rename post-commit).
2. [IDEM] ORDRSP send-once guard is a racy search_count on the filename (models/edi_order_review.py:331-349): FTP ghost-success (data stored, 226 lost → EDIFTPError → ack_sent/error) makes the ACTIVE 30-min retry cron re-upload after the VAN may have swept the first file — SAP gets two ORDRSPs. Fix: write a committed 'sending' claim row before upload / partner-side interchange dedup.
3. [IDEM] _find_existing_so matches client_order_ref alone — no partner, no company, no source filter (models/edi_processor.py:814-818); with Animates' '{po_number}' template any colliding pre-existing ref silently suppresses the real order as duplicate_skipped. Fix: scope the search to edi_trading_partner_id (+company) — mandatory before Animates.
4. [IDEM missed] Reset + re-approve never re-sends: action_reset_to_review (edi_order_review.py:245-254) lets a manager correct quantities, but the original ack_sent/success log row still matches the identical exchange filename (:331-339) so the corrected ORDRSP is silently never sent — Briscoes keeps stale confirmed quantities. Fix: clear/supersede the sent-log on reset, or add an attempt counter to the exchange key.
5. [STOCK] Reservation is neither forced nor verified: no action_assign/reservation_method reference anywhere in mml_edi; if the DC picking type is 'manual' or 'by_date' (commitment dates ARE set from EDI dates, edi_processor.py:388-391), free_qty never decrements and every subsequent order is promised the same units. Fix: preflight-assert reservation_method='at_confirm' on the DC outgoing type + verify reservation after confirm (edi_processor.py:468-469).
6. [STOCK] ORDCHG qty increases bypass all stock gating: apply_change_order writes product_uom_qty directly (edi_processor.py:773-779), no availability check, no shortfall update; the ACK then confirms the raised qty with no ABGRU (briscoes_idoc.py:363-368,456). [STOCK missed] Multi-IDOC inbound file → cross-PO-corrupted ORDRSP: review.edi_raw_data stores the WHOLE file (edi_processor.py:299) and generate_ack echoes EVERY <IDOC> in it while gathering confirmations only for the triggering PO (briscoes_idoc.py:294-299,319-322) — if EDIS batches two POs per file, each ACK emits wrong/force-rejected segments for the other PO.
